Drillr · old-drillr-social

Making the classic carousels

The older look: an off-white slide, a heavy black headline across the top, an app screenshot standing on a drop shadow underneath. One command makes one, it all runs on your own machine, and none of it costs anything.

This is not the other tool

If you have used drillr-social, most of it will feel familiar. The parts that differ are the parts that catch people.

old-drillr-social and drillr-social are two separate tools that happen to share a font file and the same four commands. Different slides, different look, different copy rules. They keep separate queues and separate photo folders, so running one never touches the other's work.

Three things are genuinely different here, and each one has its own note further down: the photo folders care about the shape of a photo, the finished slides have black bars top and bottom on purpose, and the copy rules allow something the other tool forbids.

What it actually does

Four steps, and the second one is a person.

  • plancopy gets drafted
  • approveyou read it
  • renderslides get drawn
  • publishupload

A post moves draft → approved → rendered → posted and cannot skip a step. That is deliberate: render only looks at approved posts, so nothing can be drawn, let alone posted, until a human has read the words. It is the whole reason this is four commands instead of one.

The part worth knowing up front

plan is the only command that talks to an API, and the only one that costs money. You can skip it entirely. brief puts the exact same request on your clipboard, you paste that into any Claude you already have, and import reads the answer back off the clipboard. Same copy rules, same review gate, no account needed.

node slideshow.mjs go chains all four steps into one command and keeps the gate - it stops on each carousel and waits for you to say yes. That is the one to use day to day.

The seven slides

Fixed. The order never changes and neither does what sits on each slide.

  1. Hook photo
  2. 1.Drillr icon
  3. Daily session
  4. Position tips
  5. Diet
  6. Progress
  7. Download now

a headline gets written for this slide fixed copy, never changes

So five lines get written per carousel: the hook, and one headline for each of the four app screenshots. Slide 2 always reads 1.Drillr and slide 7 always reads Download now and Start improving over Link in bio. Those two live in config.json under fixed.

The four app screenshots are real captures kept in assets/screens/. They do not change between carousels. Only the headline over them, and the two player photos on slides 1, 6 and 7, are different each time.

Why the number is on slide 2

The hook frames the carousel as a short list of apps worth having, and 1.Drillr is the first entry in that list. Drop the number and the hook stops making sense. It is a countdown that happens to have one item in it, which is exactly how the originals were built.

Before you start

Three things, and only one of them takes any real time.

Node 20 or newer
Drives everything. nodejs.org/en/download - take the LTS build. Check it with node --version.
Python 3
Draws the slides. python.org/downloads. On Windows, tick Add python.exe to PATH in the installer - it is off by default and nothing works without it.
About 25 photos
Your own. This is the real work, and the shapes matter - see step 4.

No GitHub account, no git, no npm install. Everything else is in the zip.

Windows: the two things that stop everyone

Neither is a bug in the tool. Both look like one. If you are on Windows, read this before Setup and you will skip about half an hour.

  1. The zip unpacks into itself

    Windows' built-in extractor makes a folder called old-drillr-social and puts the real old-drillr-social inside it. You end up one level too high, and Node says the file does not exist:

    what you see
    Error: Cannot find module 'C:\Users\you\Desktop\old-drillr-social\slideshow.mjs'
    code: 'MODULE_NOT_FOUND'

    Run dir. If it lists another old-drillr-social instead of slideshow.mjs, go one level deeper:

    terminal
    dir
cd old-drillr-social
node slideshow.mjs          # now it prints the command list

  2. pip is not recognized

    what you see
    'pip' is not recognized as an internal or external command,
operable program or batch file.

    This almost never means Python is missing. It means it was installed without being added to PATH, which is the default. Find out which:

    terminal
    py --version

    If that prints a version, Python is on the machine and only PATH is wrong. If it also fails, there is no Python yet. Either way the fix is the same: reinstall from python.org/downloads, taking the plain Windows installer (64-bit) rather than the big yellow install-manager button, and tick Add python.exe to PATH on the first screen.

    If the installer opens on Modify Setup instead, that version is already there and you only need to switch the option on:

    click through
    Modify  ->  Next  ->  Advanced Options
        ->  tick "Add Python to environment variables"
        ->  Install

    Then close the terminal and open a new one - an already-open window keeps the old PATH forever - and check:

    terminal
    python --version
pip install Pillow

    python --version has to print a version here. If it opens the Microsoft Store instead, Windows' stub is shadowing the real thing: Settings -> Apps -> Advanced app settings -> App execution aliases, and switch off both python.exe and python3.exe.

Why PATH specifically, and not just pip

Installing Pillow with py -m pip install Pillow works and is tempting, but it only gets you past this one message. The tool runs the literal command python when it draws slides and when it self-checks, so with PATH still broken, doctor reports Pillow missing even though you just installed it, and render fails outright. Fix PATH once and both go away.

If you ended up installing a second version alongside an older one, run pip install Pillow again after the PATH fix. Pillow went into the old Python; python now points at the new one. Having both installed is harmless.

Setup

Do these in order. Ten minutes, plus however long you spend picking photos.

  1. Unzip it

    Extract it anywhere you like. Open a terminal in the folder it makes - every command below is run from there.

    terminal
    cd path/to/old-drillr-social
node slideshow.mjs          # prints the command list

    If that prints a list of commands, you are set. There is nothing to install - the tool runs on Node's built-in modules alone, and the one package listed in package.json is for plan, which you are not using.

  2. Install Pillow

    terminal
    pip install Pillow

    This is the image library that renders the slides. Nothing else to install.

  3. Fetch the font

    terminal
    node slideshow.mjs fonts

    Pulls Archivo Black from Google Fonts. Just the one, and there is nothing to choose: it is the face the original carousels were set in, confirmed by measuring the letterforms in them rather than by eye. Leave it alone.

  4. Fill the two photo folders

    Nothing downloads them - you choose them, the tool rotates through them and remembers what it used.

    where they go
    backgrounds/landscape/   ← 15+  about 3:2, wide
backgrounds/portrait/    ← 8+   about 2:3, tall

    These two are not interchangeable

    This template shows every photo at its own shape. It never crops one to fill a slot. So a tall phone wallpaper dropped into landscape/ does not fill the wide slot on the hook slide - it renders as a narrow strip floating in the middle of it, which looks like a broken renderer and is not.

    landscape/ feeds slide 1 and slide 7. Roughly 3:2, one player, action or celebration, framed so the subject survives being shown about 700px wide. portrait/ feeds only the player shot beside the screenshot on slide 6, and is the one place a tall photo is right.

    jpg, png or webp, about 1200px on the long edge or bigger. A thin folder does not break anything - you get repeats and a warning rather than a failed run - but the same photo twice in one carousel reads as a bug.

  5. Check it over

    terminal
    node slideshow.mjs doctor

    Prints every dependency, both photo counts, every fixed picture the slides need, and what is in the queue. A line reading -- ANTHROPIC_API_KEY unset is fine and expected - that is the free path working as intended, not a problem to fix.

Making a carousel

The loop you will actually run.

Start here: one command does all of it

terminal
node slideshow.mjs go

It puts the brief on your clipboard, waits while you paste it into a chatbot, reads the reply straight back off your clipboard, shows you each carousel, and renders the ones you approve. No files to create, nothing to copy out of the terminal window.

It still stops and asks before anything renders. You type y to approve a carousel or press Enter to leave it as a draft. Everything below is the same loop done a step at a time, which is worth reading once so you know what go is doing on your behalf.

  1. Get the brief

    terminal
    node slideshow.mjs brief --count 3

    Prints what Drillr is, the copy rules, a description of what each of the four screenshots shows, and every hook used so far so the assistant can pick a fresh angle. It also puts the whole thing on your clipboard, so there is nothing to select out of the terminal.

  2. Paste it into a chatbot

    Claude, ChatGPT, Gemini, whatever you already use - the brief carries all its own context, so nothing depends on which one. Free tiers are fine. It comes back with a JSON array. Copy that reply.

    Do not bother tidying it. If it wraps the JSON in a sentence or a code fence, the importer finds the array anyway.

  3. Import and read it

    terminal
    node slideshow.mjs import

    Reads your clipboard. There is no file to make.

    If you would rather use a file

    import takes the reply from whichever of these it finds first, so the old way still works:

    terminal
    node slideshow.mjs import --from drafts.json   # a file you create
node slideshow.mjs import --paste             # force the clipboard
... | node slideshow.mjs import               # piped in

    Nothing ships a drafts.json and no command writes one - if you go that route you create it yourself, beside slideshow.mjs. On Windows, check your editor did not save it as drafts.json.txt.

    Prints each carousel as it queues it, and flags anything off - hype words, invented statistics, a hook already in the queue, a headline long enough to wrap to three lines. Fix wording directly in state/queue.json; the text fields are all free text.

    The length warnings are about the drawing, not the writing

    A feature headline over 60 characters gets flagged because at this size it wraps to a third line of heavy type and pushes the screenshot down out of the slide. Under 25 and it renders as one short line with a lot of white space above the phone. Both are worth fixing before you approve; neither stops the render.

  4. Approve

    terminal
    node slideshow.mjs list          # see the queue
node slideshow.mjs approve all

    This is the gate. Nothing renders until you do this, and doing it means you read the copy.

  5. Render

    terminal
    node slideshow.mjs render all

    Writes out/<id>/01.jpg through 07.jpg at 1080×1920, plus a caption.txt with the hashtags already attached. That folder is the finished post.

  6. Post it, then close the loop

    terminal
    node slideshow.mjs publish <id> --manual

    Upload the folder to TikTok by hand, then run this. It does not talk to TikTok - it marks the post done so its hook joins the do-not-repeat list next time you run brief.

Making the original set again

If you just want the old carousels back with fresh photos.

reference-copy.json is the exact wording the original carousels used, with two typos corrected - Drill became Drillr in two headlines, and a stray comma came out of "Drill gives, you tips". It imports like any other draft file:

terminal
node slideshow.mjs import --from reference-copy.json
node slideshow.mjs approve all
node slideshow.mjs render

You can only do this once as-is: the importer skips a hook that is already in the queue, so a second run says so and queues nothing. Change the hook if you want it twice.

Things that look wrong and are not

Four of them, and all four are the template doing what it is supposed to.

The black bars top and bottom

The finished JPEGs are 1080×1920, and only the middle 1003 pixels carry the off-white slide. That is what the originals are. A TikTok photo post is shown fitted to the width of a tall screen with black filling the rest, and the old slides were made at the shape that produces. Rendering the bars into the file gives you the old look at full 9:16 rather than a stretched approximation of it. Do not crop them off.

The phone screenshot runs off the bottom edge

On slides 3 to 6 the app screenshot is cut off by the bottom of the off-white area. That is the template, not a crop bug - the originals do exactly this, and it is what makes the phone read as standing on the slide rather than sitting on it.

Slide 6's headline is smaller than slides 3 to 5

Deliberate, and measured off the originals. Slide 6 is the only one carrying two pictures, and the screenshot gets pushed down by whatever the headline takes, so the type is set smaller there to leave room. Making them match would cost you the top of the progress screen.

The copy names features, which the other tool forbids

The standing rule for Drillr copy is sell the outcome, never list what the app contains. This template is a feature tour - four slides of app screenshots with a label over each - so the rule is bent in exactly one place: a headline may name the screen it sits over, and must then say what that screen does for the player.

the line
yes   Drillr builds your weekly plan with drills for your position
yes   Drillr tracks your progress every step of the way
no    Log calories, macros, water intake and pre-match meals
no    Radar chart, pro tips and four attribute scores

Everything else carries over unchanged. No invented numbers, no promising anyone a trial or a scout, nothing implying users can see each other.

Changing how it looks

Only if you need to. None of this is required to make a post.

Replacing the app screenshots

The four captures live in assets/screens/ as home.jpg, tips.jpg, diet.jpg and progress.jpg. Re-shoot them, drop the new files in under the same names, and nothing else changes - the renderer scales each one to the slot and keeps its own shape.

If a new screenshot shows something different from the old one, update the matching brief line in config.json too. That text is what tells the copy model what the slide is showing, and it is the only thing standing between you and a headline about the diet tab sitting over the progress screen.

Checking a render against the originals

The geometry in this tool was measured, not eyeballed, and the measuring is still there:

terminal
python render.py --calibrate path/to/original/slides
python render.py --calibrate out/<id>

It finds the off-white area in each image, works out where the headline lines and the pictures sit, and prints them as fractions. Run it on both and the two lists read the same, line for line. If you change something in render.py and want to know whether you broke the resemblance, this answers it in a way that looking at the pictures does not.

Changing the fixed lines or the slide order

config.json holds the whole script: which screen each slide shows, which photo folder it draws from, what the copy model is told about it, and the fixed text on slides 2 and 7. Editing it changes the drafting prompt at the same time, because nothing restates the script anywhere else.

One catch: a post drafted before you changed the script will refuse to render rather than draw a slide with no copy on it. It tells you so and points at state/queue.json. Add the missing line there, or delete the post and draft it again.

What does not work yet

So you do not go hunting for a bug that is not there.

Automatic posting is off

publish without --manual is a dry run. It prints what it would have sent and stops. This is deliberate and the blockers are TikTok's: photo carousels can only be pulled from a domain verified in TikTok's developer portal, and until an app passes their audit every post lands visible only to the poster. Uploading by hand is the current answer.

It is the same account and the same audit as the other tool, so clearing it once clears it for both.

If something breaks

The things that actually go wrong.

go says the clipboard still holds the brief

You pressed Enter without copying the assistant's reply, so the brief go put there is still the thing on the clipboard. Copy the reply and run go again - it checks for this on purpose, because the alternative is a JSON parse error on 80 lines of prompt.

import says no such file: ...drafts.json

Only happens if you passed --from. Without it, import reads your clipboard and there is no file involved at all - so the quickest fix is usually to drop the flag.

If you do want the file: you create it yourself, beside slideshow.mjs. Nothing ships one and no command writes one. On Windows, check the name is not drafts.json.txt.

render says a photo folder is empty

Exactly what it says: nothing in backgrounds/landscape/ or backgrounds/portrait/. The message prints the full path and which shape belongs there. Run doctor for both counts.

A photo came out as a narrow strip in the middle of the slide

A tall photo went into backgrounds/landscape/. Photos are never cropped to fill a slot here, so a 9:16 wallpaper in a wide slot renders at its own shape with white either side. Move it to backgrounds/portrait/, or crop it wide first.

A headline wrapped to three lines and squashed the screenshot

The copy is too long. The renderer shrinks the type by up to a fifth to keep a headline on two lines, and past that it gives up and takes the third line rather than shrinking into illegibility. import warns about this at 60 characters. Shorten the line in state/queue.json and re-render.

render.py failed

Almost always Pillow missing. Check with python -c "import PIL" - silence means it is fine, an error means run pip install Pillow again and read what it says.

On Windows there is a second cause: typing python opens the Microsoft Store instead of running anything. That means Python is not properly on your path - reinstall from python.org with Add python.exe to PATH ticked.

The post has no copy for some slides

The post was drafted before config.json's script changed, so it is missing a headline the script now asks for. Rather than draw a blank slide, render stops and says how many are missing. Add them in state/queue.json, or delete the post and draft it again.

nothing approved / nothing rendered

Not an error. It is the state machine telling you the previous step has not been done. Run list to see where each post has got to.

import skipped one of my carousels

Either it had no hook, or that hook is already in the queue. It prints which and why. Duplicates get skipped rather than queued twice.

There is a README.md in the zip with the rest of it - how the geometry was worked out from the original slides, the full copy rules, and what turning on auto-posting would take.
